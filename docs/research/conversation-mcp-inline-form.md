# 在消息流复用 MCP 设置表单

> 用户定稿：2026-10-29。替代已关闭 PR #7673 的扩大方案。
> 目标只有一项：把设置里的 MCP 新建表单放进任务消息流，沿用原有保存和连接流程。

## 范围

- 复用 `McpServerDialog` 的字段、校验、主题、文案和保存逻辑；设置入口继续使用原有弹窗。
- 任务入口完整展开同一表单，随消息滚动；不在表单内部增加滚动条，不移动底部输入框。
- Agent 通过宿主工具请求打开表单，只能建议公开名称、地址和 HTTP/SSE；凭证由用户在表单填写。
- 表单直接调用现有 `renderer/lib/customMcpServers.ts`，继续使用既有 MCP CRUD、safeStorage 和刷新机制。
- 仅将保存完成或取消的无凭证结果返回调用工具；输入值不进入消息、模型参数、结果或持久聊天状态。

## 不属于本次实现

- 不修改数据库 schema、migration、journal 或 snapshot，不增加保存回执表。
- 不修改凭证格式、存储文件、safeStorage 读写接口或设置页编辑语义。
- 不增加独立的连接验证器、网络访问规则、鉴权代理或 MCP provider 装配路径。
- 不修改 Claude/Codex/Pi 的启动和权限策略，不修改 system prompt、插件基座或全局账号恢复。
- 不自动重启其他运行中的任务，不增加后台续跑或配置结果轮询工具。
- 不新增手机或 SSH 配置入口。远程只沿用本机确认提示，不能操作该表单。

## 接线

1. 一个 `request_mcp_setup` 宿主工具发起本机表单请求。主进程绑定真实任务、账号和运行实例。
2. 复用已有宿主确认模式：内存中保留请求并等待用户结果，通过现有 interaction 推送和恢复查询展示。
3. Renderer 在消息流的宿主内容区挂载同一个 `McpServerDialog`，仅增加嵌入呈现参数。
4. 用户点击保存，执行原有新建配置和 Token 保存逻辑；失败沿用原有错误反馈，表单可继续编辑。
5. 保存成功后将 server id 和 saved 状态返回宿主；取消只返回 cancelled。响应不携带 URL、请求头或 Token。
6. 工具等待正常结算，沿用引擎的工具结果链继续，不另建自动续跑通道。Stop、关任务或切账号取消未完成请求。
7. 保存后的生效范围沿用设置行为：provider 刷新及既有忙碌延期机制，不承诺当前运行实例立即获得新工具。

## 数据和兼容边界

沿用当前主干的 MCP 表、`mcp_token_<id>` 与 settings 保存入口。
旧配置无需编辑、转换或重新授权；HTTP/SSE、Token、自定义请求头和三种引擎维持原有能力差异。
本机表单仅短暂持有输入，不把表单值放入通用回答组件或聊天 store。
临时请求只活在当前主进程；应用重启后重新请求表单，不建立持久操作账本。
已关闭 PR 的验收 profile 和加密文件保留原样，不迁移、降级、删除或复制用户数据。

## 验收

- 设置页与消息流使用同一生产表单；新建、编辑、Token 保留/替换/清除和请求头保存沿用旧路径。
- 消息流完整展开，滚轮带动消息和表单，底部输入框固定；重新渲染及长历史不丢正在填写的输入。
- 保存成功只提交一次；失败可继续修改；取消、Stop、切账号和关任务后不能操作旧请求。
- 远程猜到 request id 也不能确认；工具结果和请求快照均没有用户填写的凭证。
- Light/Dark 与五语言使用原有语义 token 和翻译；UI 截图使用模拟数据。
- 最终 diff 中数据库、凭证存储、自定义 MCP provider 实现、三种引擎实现和插件基座路径均应为零变更。
- 新 PR 按真实测试结果和未验证范围交付，不复用旧 PR 的通过结论。
